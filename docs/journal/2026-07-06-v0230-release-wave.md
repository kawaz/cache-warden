## リリースのハマり所: notarize 403 (PLA 再同意)

Release workflow が Notarize step で `HTTP 403. A required agreement is missing or
has expired` により失敗 (rerun でも同一 = transient でない)。Apple Developer の
License Agreement 再同意が必要で、**kawaz の Apple ID 操作でしか解消できない**。
macos-signing skill の「notarize 403 PLA 再同意」既知パターン。

**解決 (同日)**: kawaz が PLA 再同意 → 同意直後の rerun はまだ 403 (runbook の
「1 分以内に反映」より遅い) → **5 分待って rerun したら成功**。skill runbook の
伝播時間の記述は楽観的すぎる場合がある (数分待ってからの rerun を推奨)。

### brew upgrade 事故と復旧 (on-success-release 中)

`brew upgrade --cask` が「0.21.0 -> 0.24.0」と誤認識して開始し、
`.metadata/0.21.0` の rename 失敗で中断。**app 削除 + binary unlink まで進んで
止まった** (= CLI 消失。daemon は削除済み inode を掴んで生存、signing 無事故)。

- 根本原因: Caskroom に v0.21.0 時代の残骸 version ディレクトリが残っており、
  brew の installed version 認識が INSTALL_RECEIPT と食い違っていた
- 復旧: 残骸 `0.21.0.upgrading` を退避 → `brew reinstall --cask` で 0.24.0 導入、
  app/binary とも復旧確認
- daemon は v0.23.0 のまま稼働継続 (plist は /Applications の app を指すため、
  次回再起動で自動的に 0.24.0 に乗る)
