# Phase 1.4: approver IPC (unix socket + serde_json wire schema)

draft-DR-0031 Phase 1.4 を land した記録。実装は sonnet5-worker-high への委譲
(Workflow: 実装 → fresh 検証 + opus47 レビューの 2 phase)、レビュー指摘の修正は
メインセッションで適用。

## 実装の形

- `crates/cache-warden-approver/src/wire.rs` (新設、approver crate に lib target 追加):
  DR §4 準拠の `ApproveRequest` / `ApproveResponse` / `Outcome` ほか。serde/serde_json
  は target-gate なし (純データ型)、objc2 系は macOS gate のまま
- `crates/cache-warden-approver/src/main.rs`: `--socket <path>` /
  `CACHE_WARDEN_APPROVER_SOCKET` で daemon に connect → request 1 行 read →
  「Allow <requester> to read <key>」サマリ → outcome 確定で response 1 行 write。
  Cancel は `NSApplicationWillTerminateNotification` observer + `WireConn`
  (`Arc<Mutex<Option<_>>>` の take-once) で Approved との二重送信を防止
- `crates/cache-warden-cli/src/daemon/approver.rs` (新設): bind (stale 検知 + 0600、
  control.sock と同パターン) / spawn_helper / exchange / request_approval。
  fake helper (tokio task) で round-trip・timeout・version reject をテスト、
  実 helper / TouchID は一切発火させない

## ハマり所 → 解決策

- **DR §4 本文 (helper が listen) と継続指示 (daemon が bind) の矛盾** →
  daemon bind + helper connect で確定 (socketpair 最終形への収束、socket file
  責務の daemon 集約、connect 失敗 = daemon 不在の単純化)。DR に
  「§Phase 1.4 実装記録」として supersede を明記
- **timeout が response 受信のみだと `accept()` が無期限ハング** (connect 前に
  helper が死ぬと詰む。worker は「connect しない helper のテストがハング確定」
  に気づいてテストを削除していた) → timeout を exchange 全体 (accept + send +
  recv) に拡大。削除されていたテストも `exchange_times_out_when_no_helper_ever_connects`
  として復活
- **`--socket` 指定時の IPC 失敗が standalone 表示にフォールバックしていた**
  (opus47 レビュー Medium-1): 承認対象を表示しない偽 dialog で TouchID を求め、
  承認しても daemon は timeout で fail-closed する UX 矛盾 → dialog を出さず
  exit(1) の fail-fast に変更。standalone 表示は socket 指定なし専用
- **`v` フィールドを追加したのに受信検証が両側ゼロ** (レビュー Low-1) →
  helper / daemon 両側で不一致 reject + テスト追加
- **spawn した Child の orphan dialog リスク** (レビュー Low-3) →
  `kill_on_drop(true)`。daemon 側が Child を drop したら誰も待っていない承認を
  ユーザに求め続ける dialog を残さない
